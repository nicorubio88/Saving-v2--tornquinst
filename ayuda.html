Cómo funciona el sistema

Esta página explica de punta a punta cómo funciona la app: de dónde salen los números, cómo se calcula cada cosa, y qué hacer en cada pantalla. Pensada para nueva gente del equipo o para repasar antes de una auditoría de datos.

1. Arquitectura: de dónde salen los datos

No hay una base de datos tradicional: Google Sheets es la base de datos. Un backend en Google Apps Script lee y escribe esa planilla, y expone una API web (el "Web App"). El frontend es un sitio estático (sin servidor propio) que solo consume esa API — por eso hostearlo es gratis o casi gratis (DigitalOcean Static Site o GitHub Pages).

Consecuencia práctica: si algo no aparece o no se actualiza, casi siempre es porque falta re-implementar el Web App ("Implementar → Nueva versión") después de pegar código nuevo en Apps Script — el editor puede mostrar el código nuevo mientras la URL /exec sigue sirviendo el viejo. Se puede verificar abriendo <URL_DEL_WEB_APP>?action=version en el navegador.

3. Cómo se calcula el ahorro de un período

Este es el corazón de toda la app. Cada vez que cargás una medición (ej: kWh y toneladas de una semana), pasa esto:

flowchart LR V["Valores cargados
ej: kw=180.000, ton=1.200"] --> IND["Fórmula del indicador
ej: kw / ton"] IND --> RES["Indicador del período
ej: 150 kWh/ton"] RES --> DIF["Diferencia vs línea de base
ej: 145 − 150 = −5"] DIF --> COSTO{"¿Costo fijo
o variable?"} COSTO -->|"fijo"| CF["Número fijo del proyecto"] COSTO -->|"variable"| CV["Se lee de una variable
cargada ESE mismo período
(ej: precio_gas)"] CF --> MULT["Diferencia × Costo"] CV --> MULT MULT --> VOL["× Variable de volumen
ej: × 1.200 ton"] VOL --> AHORRO["💰 Ahorro del período"] style AHORRO fill:#dcefc9,stroke:#3D5F26 style COSTO fill:#fdeacb,stroke:#c98a12

Por qué el costo puede ser "variable": si el precio de un insumo cambia mes a mes (gas, energía), un costo fijo obligaría a recalcular TODO el histórico cada vez que se edita — distorsionando meses pasados. Con costo variable, cada mes se carga con su propio precio real y queda valuado a ese precio para siempre, sin importar qué pase después.

"Nivel de indicador" es el más potente: separa lo que controlás (la eficiencia, ej. bajar de 145 a 130 kWh/ton) de lo que no controlás (el precio de la energía). El objetivo en $ se deriva solo con el costo vigente — si el costo es variable, se recalcula con el precio de CADA mes, igual que el ahorro real.

⚠️ Error común: si la línea de base y el objetivo apuntan en un sentido pero "Sentido de la mejora" está configurado al revés (ej. base=0 apuntando a un número MÁS ALTO, pero marcado como "menor es mejor"), la resta da negativa y no hay meta calculable. La app avisa esto explícitamente en el detalle del proyecto.

Todo lo que ves en el dashboard (KPIs, gráficos, Pareto, alerta) se recalcula al vuelo desde los registros — no hay números "guardados" que puedan quedar desactualizados. Filtrar por fecha o por estado del proyecto recalcula todo en conjunto, no solo el gráfico.
